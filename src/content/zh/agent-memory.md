## 为什么记忆是 Agent 的核心 {#why}

回顾标准 Loop：每一轮，模型都要看到完整的推理轨迹才能做出一致的决策。轨迹越长，上下文越满，最终要么超限崩溃，要么被迫丢掉早期关键信息。**记忆系统就是解决"上下文不够用"的工程层。**

## 三层记忆模型 {#three}

| 层级 | 载体 | 内容 | 生命周期 |
|---|---|---|---|
| **工作记忆** | 上下文窗口 | 当前任务、最近几轮思考与观察 | 单次任务内 |
| **短期记忆** | 对话历史 / 推理轨迹 | Thought-Action-Observation 序列 | 会话期间 |
| **长期记忆** | 向量库 / 数据库 | 跨会话的事实、偏好、知识片段 | 持久化 |

可以类比人脑：工作记忆是"手头正在想的事"，短期记忆是"刚才说了什么"，长期记忆是"我知道的世界"。MRKL 里的**知识库模块**，本质上就是显式的长期记忆。

## 上下文管理的四种策略 {#strategies}

| 策略 | 做法 | 优点 | 代价 |
|---|---|---|---|
| 滑动窗口截断 | 只保留最近 N 轮 | 零成本 | 丢失早期信息 |
| 摘要压缩 | 旧轨迹交给 LLM 总结 | 保留要点 | 每次摘要消耗 token |
| 向量检索 | 历史存入向量库，按相关性取回 | 可按需召回 | 需要外部存储与嵌入 |
| 工具结果截断 | Observation 超长只取前几 KB | 防撑爆 | 可能丢关键细节 |

## 记忆的写入与检索 {#flow}

```
写入：每轮结束后
  ① 抽取值得记住的信息（实体、结论、关键数据）
  ② 向量化 → 存入长期记忆库

检索：每轮开始前
  ① 把当前目标/问题向量化
  ② 相似度检索 Top-K 相关记忆片段
  ③ 与工作记忆一起拼进 prompt
```

关键原则：**不是把所有历史都塞回去，而是把"与当前最相关的"找回来**——这既省 token，又避免无关历史干扰推理。

## RAG 作为长期记忆 {#rag}

检索增强生成（RAG）是长期记忆最常见的落地形态：文档/知识库切块 → 向量化入库 → 问答时检索相关片段。它与 Agent 结合时：

- 把 RAG 当作一个**检索工具**挂进工具注册表（MRKL 视角：一个专家模块）；
- 让 Agent 自行决定"何时需要查资料"，而不是每次都查——省成本、减少幻觉来源。

## 挑战与对策 {#challenges}

- **记忆污染**：写入了错误/过时的信息 → 写入前做置信度过滤，长期记忆定期刷新；
- **检索冲突**：召回片段与当前事实矛盾 → 检索结果标注来源，让模型做判断；
- **成本放大**：摘要 + 向量化都要额外 token → 只在阈值触发时启用，日常用滑动窗口。

## 总结 {#conclusion}

> 记忆系统决定了 Agent 的"格局"：没有记忆的 Agent 每轮都失忆，有了分层记忆的 Agent 才能处理跨会话、跨数据源的真实任务。工程上的口诀是——**能塞进去的少塞，该记下来的持久化，需要时按相关性召回**。
