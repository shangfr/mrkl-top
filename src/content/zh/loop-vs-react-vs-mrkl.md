## 各自定位（一句话版） {#position}

| 概念 | 本质 | 回答的问题 |
|---|---|---|
| **MRKL** | 系统架构（静态组织方案） | "系统有哪些能力？任务该分给谁？" |
| **ReAct** | 决策协议（模型输出格式与推理模式） | "模型每一步该如何思考和行动？" |
| **Agent Loop** | 执行引擎（运行时控制流） | "整个流程如何反复推进、如何终止？" |

## 分层关系图 {#layers}

```
┌─────────────────────────────────────────────┐
│  Agent Loop（执行引擎）                      │
│    while 未终止:                            │
│        ┌─────────────────────────────┐      │
│        │  ReAct 决策协议（每一轮内部）│      │
│        │  Thought → Action → Obs     │      │
│        └──────────────┬──────────────┘      │
│                       │ 调用                │
│        ┌──────────────▼──────────────┐      │
│        │  MRKL 组织架构（工具/模块）  │      │
│        │  Router + 专家模块注册表     │      │
│        └─────────────────────────────┘      │
└─────────────────────────────────────────────┘
```

**Loop 是"骨架"，ReAct 是"大脑每轮的工作方式"，MRKL 是"手和资源怎么摆放"。**

## 逐维度对比 {#table}

| 维度 | MRKL | ReAct | Agent Loop |
|---|---|---|---|
| 提出者 / 来源 | AI21 Labs（2022 论文） | Google / 普林斯顿（2022 论文） | 工程概念（LangChain 等框架实现） |
| 抽象层 | 架构层（静态） | 推理层（模型行为） | 运行时层（控制流） |
| 核心组件 | 路由器 + 专家模块 | LLM 单模型 + 工具，Thought/Action/Observation 推进 | LLM + 工具 + 记忆 + 终止条件 + 状态管理 |
| 决策方式 | 前端一次性"分诊"，任务移交专家模块 | 模型每步自主决策，规划与执行交错 | 框架驱动循环，模型每轮产出决策 token |
| 纠错能力 | 弱（路由错后难回头） | 强（Observation 反馈可修正） | 取决于内部模式（用 ReAct 模式则强） |
| 可扩展性 | 最强（模块隔离，可独立增删） | 中（扩展 = 往 prompt 加工具描述） | 视实现（状态图式 Loop 扩展性强） |
| 可解释性 | 中（路由可审计，模块黑盒） | 强（思维链全程可见） | 视实现（显式状态图则强可观测） |
| 典型场景 | 生产系统、分域任务 | 开放式多步推理、试错任务 | 一切 Agent 应用（通用底座） |
| 代表实现 | AI21 Studio、模块化 Agent 设计 | ReAct 提示词模板、LangChain ReAct 风格 | LangGraph、OpenAI Agent SDK、AutoGen |

## 三者如何协同：一个完整例子 {#example}

假设任务：**"计算上证指数近 30 日收益率，并写一份分析报告。"**

- **MRKL 层（组织）**：模块注册表里有 `stock_api`、`calculator`、`report_writer` 三个专家模块；路由器（LLM）判断任务涉及数据获取 + 计算 + 生成，把前两步交给对应模块。
- **Loop 层（引擎）**：循环开始，迭代计数 = 0，上下文 = 任务目标 + 工具描述。
- **ReAct 层（每轮决策）**：

```
Thought: 先取近30日收盘价
Action: stock_api["get_prices", "上证指数", 30日]
Observation: [3245.2, 3260.1, ..., 3310.5]

Thought: 计算收益率 = (最后-最先)/最先
Action: calculator["return_rate", 3310.5, 3245.2]
Observation: 0.0201

Thought: 数据齐了，生成报告
Final Answer: 近30日收益率为 2.01%，...
```
- **Loop 层（收尾）**：检测到 `Final Answer` → break，返回答案；若超过 max_iterations（比如第 4 轮还在打转）→ 强制终止，防止死循环。

## 一个类比帮助记忆 {#analogy}

把三者放进"医院"场景：

- **MRKL = 医院的组织架构**：分诊台 + 内科 + 外科 + 检验科……（能力和科室怎么划分）；
- **ReAct = 医生的诊疗方式**：先问诊（Thought）→ 开检查（Action）→ 看报告（Observation）→ 再判断，边查边修正；
- **Agent Loop = 医院的就诊流程引擎**：挂号 → 分诊 → 检查 → 复诊 → 出院的闭环循环，含超时限制和风险控制。

## 结论 {#conclusion}

> **MRKL 决定"系统有什么、谁来做"，ReAct 决定"模型每轮怎么想怎么做"，Agent Loop 决定"这个过程怎么转起来、何时停"。**三者是互补的层次关系而非竞争关系。主流框架的默认 Agent（如 LangGraph + ReAct 风格 prompt + 工具注册表）就是三者的合体；框架之间的差异，本质上是这三层各自实现细节的差异。
