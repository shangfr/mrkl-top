| 项目 | 内容 |
|---|---|
| 题目 | MRKL Systems: A Modular, Neuro-Symbolic Architecture that Combines Large Language Models, External Knowledge Sources and Discretized Reasoning |

| 核心主张 | 不要把所有能力塞进一个 LLM——让路由器和专家模块分工 |

## 三大动机：LLM 的已知短板 {#motivation}

- **计算不可靠**：LLM 是"语言模型"，不是"计算器"。多位数的算术、符号运算经常出错；
- **知识过时**：训练数据有截止日期，无法回答"刚刚发生"的事；
- **难以定制专长**：给通用模型注入特定领域知识，成本高且难以更新。

论文的洞察是：这些问题**不该靠把模型变大来解决**——把任务路由给确定性的外部系统，又快又准又便宜。

## 核心设计：路由器与专家模块 {#design}

MRKL 系统由两部分组成：

- **路由器（Router）**：由 LLM 充当。它接收输入，输出一段"调用指令"，格式类似 `call: , `；
- **专家模块（Expert Modules）**：可被路由器调用的任意组件，包括：

  - 外部知识源（数据库、知识图谱、日期/事实查询）；
  - 离散推理引擎（Wolfram Alpha、计算器）；
  - 专家 LLM（领域微调模型）。

模块返回结果后，路由器把它放回自己的上下文中继续生成答案——相当于"模块是黑盒，路由是唯一的大脑"。

## 实验：把计算交给 Wolfram Alpha {#experiment}

论文的核心实验是让一个 LLM 路由器学会在数学问题上**调用 Wolfram Alpha** 模块，而不是自己硬算。结果显示：

- 算术类问题的**准确率显著提升**——计算交给确定性引擎后，错误基本消失；
- 即使某次调用失败，路由器也能把错误当作反馈，尝试其他模块或给出替代答案。

这验证了论文的核心主张：**模块化不仅更准，还让错误变得可定位、可修复**——错误要么出在路由判断，要么出在某个具体模块，而不是模型内部不可见的黑盒。

## 遗产：对后续工作的影响 {#legacy}

| 后续方向 | 与 MRKL 的关系 |
|---|---|
| ReAct（2022） | 把"路由"变成每步自主决策的循环，强化了纠错能力 |
| Toolformer（2023） | 让模型**自己学会**何时调用 API，省去手工路由规则 |
| Function Calling | 用结构化 JSON 协议替代自然语言调用指令，路由更可靠 |
| 现代 Agent 框架 | 工具注册表 + 路由 + 循环，几乎就是 MRKL 思想的工程化 |

## 局限与启示 {#limit}

- **路由一次定生死**：没有 ReAct 那样的"观察-修正"回路，路由判断错了就难回头；
- **调用格式脆弱**：自然语言的 `call:` 指令需要模型严格遵循格式，容易解析失败（后来被结构化输出取代）；
- **模块即黑盒**：专家模块内部的推理不可见，可审计性打折扣。

启示：MRKL 的短板恰好解释了为什么后来的 Agent 都采用"**ReAct 循环 + 工具注册表**"的组合——既要模块化，也要纠错回路。

## 总结 {#conclusion}

> MRKL 论文的价值不在某个具体的模型或实验，而在于它确立了 Agent 时代的一条基本设计原则：**让 LLM 做擅长的事（理解与规划），把确定性的活交给确定性的模块**。今天所有 Agent 框架，都在这条原则上生长。
