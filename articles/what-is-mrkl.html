什么是 MRKL？模块化推理、知识与语言架构全解

MRKL（Modular Reasoning, Knowledge and Language，模块化推理、知识与语言）是一种用于构建 AI 智能体的神经符号混合架构，由 AI21 Labs 于 2022 年提出。本篇文章讲清它的核心思想、工作流程与适用场景。

核心思想：路由器 + 专家模块

MRKL 的出发点是一个朴素但重要的判断：不该把所有能力都塞进一个大语言模型里。数学计算会算错，事实查询会幻觉，垂直领域需要专门的知识——与其让通用 LLM 硬扛，不如把它拆成两类组件，各司其职：

  • 路由器（Router）——由 LLM 充当。负责理解用户输入、判断该调用哪个模块，并把任务分发出去。
  • 专家模块（Expert Modules）——一系列专业化组件，包括：
    • 专家 LLM：针对特定领域微调的模型（法律、医疗、数学等）；
    • 外部知识库：数据库、知识图谱、搜索引擎；
    • 离散推理工具：计算器、符号数学引擎（如 Wolfram Alpha）、代码解释器等。

工作流程

用户输入 → 路由器（LLM）分析意图
              ├── 需要计算   → 调用计算器 / 数学引擎
              ├── 需要事实   → 查询知识库 / 搜索引擎
              ├── 需要专长   → 调用专家 LLM
              └── 通用问题   → 直接由通用 LLM 回答

路由决策发生在前端，任务一旦被分配给某个专家模块，模块内部就是一个相对独立的黑盒。这种"先分诊、后执行"的流程让整个系统像一座分工明确的医院。

与 ReAct 的定位差异

MRKL 常被拿来与 ReAct 比较——两者同年提出，但思路完全不同：

维度MRKLReAct
提出方AI21 LabsGoogle / 普林斯顿
调度方式路由器将任务分配给静态专家模块模型自己决定"思考-行动-观察"循环
模块性质模块独立、可替换、可扩展主要是工具调用，无独立专家模块
侧重点模块化、可组合、可审计推理轨迹（reasoning trace）的生成

更准确地说，MRKL 回答的是"系统如何组织能力、任务该分给谁"，ReAct 回答的是"模型现在该想什么、做什么"。两者在今天的 Agent 框架中已经走向融合。

为什么要用 MRKL

  • 准确性：数学、事实查询交给确定性工具，显著减少 LLM 幻觉；
  • 可维护性：每个专家模块独立更新，不必重训整个模型；
  • 可解释 / 可审计：路由和调用过程透明，便于追踪问题；
  • 可扩展：随时挂接新的知识库或工具，系统能力线性增长。

总结

MRKL 是 LLM 时代"工具调用 / function calling"思想的重要先驱。如今主流 Agent 框架中"LLM 做规划 + 工具做执行"的模式，很大程度上延续了它的架构思路。
