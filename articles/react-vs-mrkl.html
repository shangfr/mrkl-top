ReAct Loop 与 MRKL 的区别比较

两者都是 2022 年提出的 LLM Agent 架构，但设计哲学截然不同。一句话概括：MRKL 是"分诊台 + 专家门诊"的模块化分工架构，ReAct 是"边想边做、试错迭代"的自适应执行循环。

ReAct 的三步循环机制

ReAct（Reasoning + Acting）的核心是让 LLM 在一个循环里交替输出：

Thought（思考）→ Action（行动 / 调用工具）→ Observation（观察结果）→ Thought → ...

每一步的"思考"都显式写出来，形成一条可追溯的推理轨迹。模型不是把任务分给别人，而是自己判断何时查资料、何时算数、何时给出最终答案，并且可以在中途修正——发现思路错了就换方向。

MRKL 则是一次性"分诊"：路由器先分析输入，把整个任务移交给最合适的专家模块，专家模块内部是黑盒。

六个关键差异点

1. 规划时机

  • MRKL：先规划、后执行，路由决策发生在前端；
  • ReAct：规划与执行交错（interleaved），走一步看一步，边做边调整。

2. 错误处理与纠错

  • MRKL：路由错了就错了——任务进了错误的模块，缺少回路去纠正（这是 MRKL 的短板）；
  • ReAct：天然具备纠错能力——观察结果不对劲，模型可以在下一轮 Thought 里自我修正。

3. 可解释性

  • MRKL：路由过程可审计，但专家模块内部不透明；
  • ReAct：整个思维链（Thought）全程可见，可解释性更强，便于调试和注入约束。

4. 可扩展性

  • MRKL：强。挂一个新的知识库或专家 LLM 不需要动其他部分；
  • ReAct：弱。扩展主要靠往 prompt 里加工具描述，没有模块隔离，工具多了容易让模型混淆。

5. 性能与成本

  • MRKL：通常更快更省——一次路由、一次执行，但路由不准时准确率受限；
  • ReAct：多次工具往返，延迟和 token 成本更高，但复杂任务更灵活、成功率通常更高。

6. 适用场景

  • MRKL：结构清晰、可分域的任务（如"先查库、再计算、再生成报告"），适合对可控性和审计有要求的生产系统；
  • ReAct：开放式、多步推理任务（谜题、多跳问答、代码调试），适合需要试错和探索的场景。

现代视角：走向融合

如今主流 Agent 框架（LangChain、AutoGPT、OpenAI 的 function calling 等）其实同时吸收了两种思想：

  • 用 ReAct 式的循环作为执行主循环（思考 → 行动 → 观察）；
  • 用 MRKL 式的工具 / 模块注册表 + 路由来组织和选择能力。

所以更准确的说法是：MRKL 定义了"系统如何组织能力"，ReAct 定义了"agent 如何推进任务"——前者回答"我有什么、该用哪个"，后者回答"我现在该想什么、做什么"。两者是互补关系，而非对立方案。

结论

MRKL 决定"系统有什么、谁来做"；ReAct 决定"模型每轮怎么想怎么做"。现代 Agent 系统正是二者的合体。
