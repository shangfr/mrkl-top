Agent 的记忆系统：短期、长期与工作记忆

Agent Loop 每轮都要把"目标 + 历史 + 观察"塞进上下文——但上下文窗口是有限的。记忆系统决定了 Agent 能记住什么、忘掉什么、从哪里找回信息，是 Loop 能否跑深跑远的关键。

为什么记忆是 Agent 的核心

回顾标准 Loop：每一轮，模型都要看到完整的推理轨迹才能做出一致的决策。轨迹越长，上下文越满，最终要么超限崩溃，要么被迫丢掉早期关键信息。记忆系统就是解决"上下文不够用"的工程层。

三层记忆模型

层级载体内容生命周期
工作记忆上下文窗口当前任务、最近几轮思考与观察单次任务内
短期记忆对话历史 / 推理轨迹Thought-Action-Observation 序列会话期间
长期记忆向量库 / 数据库跨会话的事实、偏好、知识片段持久化

可以类比人脑：工作记忆是"手头正在想的事"，短期记忆是"刚才说了什么"，长期记忆是"我知道的世界"。MRKL 里的知识库模块，本质上就是显式的长期记忆。

上下文管理的四种策略

策略做法优点代价
滑动窗口截断只保留最近 N 轮零成本丢失早期信息
摘要压缩旧轨迹交给 LLM 总结保留要点每次摘要消耗 token
向量检索历史存入向量库，按相关性取回可按需召回需要外部存储与嵌入
工具结果截断Observation 超长只取前几 KB防撑爆可能丢关键细节

记忆的写入与检索

写入：每轮结束后
  ① 抽取值得记住的信息（实体、结论、关键数据）
  ② 向量化 → 存入长期记忆库

检索：每轮开始前
  ① 把当前目标/问题向量化
  ② 相似度检索 Top-K 相关记忆片段
  ③ 与工作记忆一起拼进 prompt

关键原则：不是把所有历史都塞回去，而是把"与当前最相关的"找回来——这既省 token，又避免无关历史干扰推理。

RAG 作为长期记忆

检索增强生成（RAG）是长期记忆最常见的落地形态：文档/知识库切块 → 向量化入库 → 问答时检索相关片段。它与 Agent 结合时：

  • 把 RAG 当作一个检索工具挂进工具注册表（MRKL 视角：一个专家模块）；
  • 让 Agent 自行决定"何时需要查资料"，而不是每次都查——省成本、减少幻觉来源。

挑战与对策

  • 记忆污染：写入了错误/过时的信息 → 写入前做置信度过滤，长期记忆定期刷新；
  • 检索冲突：召回片段与当前事实矛盾 → 检索结果标注来源，让模型做判断；
  • 成本放大：摘要 + 向量化都要额外 token → 只在阈值触发时启用，日常用滑动窗口。

总结

记忆系统决定了 Agent 的"格局"：没有记忆的 Agent 每轮都失忆，有了分层记忆的 Agent 才能处理跨会话、跨数据源的真实任务。工程上的口诀是——能塞进去的少塞，该记下来的持久化，需要时按相关性召回。
